# ТЗ та архітектура Revolution Launcher 1.0

## Продукт і межі поставки

Windows 10/11 x64, Python 3.12, PySide6 / Qt WebEngine, локальний HTML/CSS/JavaScript, minecraft-launcher-lib 8.0. Один користувацький профіль Windows, кілька ізольованих Minecraft-інстансів. Основний сервер: revolution.modpack.gg. Початковий модпак із 97 наданих JAR-файлів входить до Windows-поставки. Подальші оновлення адміністратор може розповсюджувати через HTTPS-маніфест.

Підтверджена користувачем пара: Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21. Додатковий legacy-профіль: Minecraft 1.12.1 / Forge 14.22.1.2485 / Java 8. Адаптація бінарних NeoForge-модів до 1.12.1 не існує; несумісні пари відхиляються.

## Потоки даних

UI опитує локальний snapshot щосекунди. Серверний статус оновлюється фоновим потоком раз на 30 секунд; DNS SRV у Windows використовує системний DNS API. Minecraft handshake запитує статус, ping/pong вимірює RTT. Maintenance API може явно встановити стан технічних робіт. Відсутні дані позначаються тире.

Тривалі операції працюють у фоні. Під час установки та гри зміни інстансу, акаунту й конфігурації блокуються. Процес Minecraft запускається списком аргументів без shell; його завершення та час гри фіксуються окремим потоком. Статус RPC базується на реальному процесі. Закриття лаунчера під час операції спершу потребує її скасування.

## Установлення Minecraft та NeoForge

Vanilla Minecraft завантажується через minecraft-launcher-lib. Для NeoForge лаунчер перевіряє SHA-256 офіційного installer JAR, читає його install_profile.json і version.json, завантажує бібліотеки та Mojang mappings із перевіркою офіційних SHA-1. Потім послідовно запускає офіційні клієнтські процесори з їхніми аргументами та перевіряє результати; крок завантаження mappings замінюється вже перевіреним локальним файлом. Це дозволяє використовувати системну TLS-довіру Python для мережевої частини. Лише після успішного завершення публікуються version JSON і маркер завершеної інсталяції. Помилки й скасування не перетворюють частково підготовлений інстанс на встановлений. Статус фактичної перевірки цього шляху наведено в QA.md.

## Алгоритм синхронізації

1. Отримати HTTPS-маніфест з обмеженням розміру.
2. Перевірити schemaVersion, сумісність, шляхи, дублікати, SHA-256 і джерела.
3. Побудувати план: справні, нові/змінені, застарілі керовані, збережені конфігурації.
4. Завантажити нові файли у staging, перевірити SHA-256 та заявлений розмір. Перевіряти скасування між блоками.
5. Перед застосуванням зберегти журнал із попереднім маніфестом; старі файли перемістити у backup.
6. Застосувати завантажені файли, записати новий маніфест, завершити транзакцію.
7. При помилці або під час наступного старту після переривання повернути резервні файли й попередній маніфест.

Сторонні локальні моди автоматично не видаляються. Вони можуть спричинити несумісність із сервером: адміністратор має використовувати чисту ізольовану збірку. Скасування на короткій фазі commit відкладене до завершення операцій.

## Інтеграції та зовнішня конфігурація

Microsoft-вхід реалізує PKCE/state у системному браузері, XBL/XSTS/Minecraft обмін через бібліотеку, refresh у системному keyring. Потрібні власний зареєстрований public client і дозвіл Minecraft API. Паролі та client secrets не збираються.

Modrinth/CurseForge отримують **зафіксовані** версії. Усі залежності включаються адміністратором у повний маніфест. Автоматичний вибір «latest» для серверного пакета не застосовується. Довільний каталог пошуку онлайн-модів і автоматичне вирішення невказаних транзитивних залежностей поза маніфестом — можливе наступне розширення.

Discord Webhook призначений для публікації повідомлень, а не читання історії каналу. Для новин ця версія читає RSS/Atom. Майбутній Discord-бот може формувати таку стрічку на стороні сервера; bot token не повинен входити в лаунчер.

## Безпека й обмеження

Локальний UI, CSP без віддалених скриптів, блокування навігації на зовнішні сторінки в привілейованому вікні, вузький JSON bridge. Зовнішні посилання відкриваються системним браузером. Refresh token та API key не передаються до UI. Захищені папки світу й профілю виключені з manifest scope; заборонені traversal, абсолютні шляхи, Windows special names і посилання у керованих шляхах.

SHA-256 підтверджує відповідність довіреному маніфесту; підпис маніфесту Ed25519 у версії 1.0 не реалізовано. HTTPS endpoint контролює адміністратор. Самі JAR-моди є виконуваним кодом і встановлюються з довіреної збірки.

У релізі немає сертифіката Authenticode, автоматичного оновлення самого лаунчера, власного backend для авторизації Revolution, серверного хостингу маніфесту для оновлень. Локальний комплект із 97 JAR-файлів входить у Windows-архів; конфігурації сервера не надані. Решта компонентів потребують окремих ресурсів власника спільноти.

## Локальний модпак у версії 1.0.1

Папка modpack поруч із виконуваним файлом містить локальний маніфест та JAR-файли. Вона підключена лише до стандартного інстансу revolution/modern за відсутності HTTPS manifestUrl. SyncEngine використовує той самий staging/journal/rollback; замість мережі копіює файли з фіксованої папки та перевіряє розмір і SHA-256 під час копіювання. Скасування перевіряється між блоками. Джерела bundle не допускаються у віддалених маніфестах. Комплект не копіюється у нові інстанси автоматично.


## Доповнення 1.1.0

`releases.py` перевіряє підпис Ed25519, профіль і монотонну ревізію за ідентичністю URL+public key. `cache.py` відновлює копії за SHA-256; кеш заповнюється після успішної транзакції, щоб не займати місце staging. `api.py` серіалізує фонову синхронізацію, ручні дії та запуск; під час гри зміни файлів заблоковані. Канал застосовується лише до стандартного інстансу Revolution.

`diagnostics.py` читає обмежені хвости власних логів, приховує відомі приватні дані та формує доказові правила. Необов’язковий HTTP-запит до Gemini/Ollama потребує підтвердження незмінного звіту, моделі й сервісу. Відповіді не мають доступу до інструментів.

`tools/` містить аудит, побудову окремого Modrinth-кандидата, підпис релізу та публікацію assets із перевіркою GitHub SHA-256. Покажчик каналу публікується останнім атомарним оновленням. Приватний ключ не входить до вихідного коду або релізу.
