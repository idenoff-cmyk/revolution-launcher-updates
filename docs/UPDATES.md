# Канал оновлень Revolution

## Для гравця

97 модів встановлюються автоматично при першому відкритті. Увімкнений віддалений канал перевіряється на старті, кожні 15 хвилин у простої та перед запуском. Під час гри модпак не змінюється.

Підпис Ed25519 підтверджує схвалення релізу власником ключа. SHA-256 підтверджує точні байти. Нижча ревізія та змінений вміст із тим самим номером відхиляються. Відкат до старого складу теж оформлюється як нова ревізія.

Обрив завантаження зберігає попередню збірку. Перед заміною нові файли завантажуються в staging; журнал транзакції відновлює перервану заміну. Сторонні моди та світи не видаляються. Кеш містить окремі копії за SHA-256; пошкоджена копія відхиляється.

## Опублікований перший реліз

- Репозиторій: `idenoff-cmyk/revolution-launcher-updates`.
- Незмінний тег: `pack-r1`. Версія: `2026.09.08`.
- Активний канал: `https://raw.githubusercontent.com/idenoff-cmyk/revolution-launcher-updates/main/channel/stable.json`.
- Готова папка: `CommunityRelease/pack-r1` поруч із вихідним кодом.

Папка містить підписаний `manifest.json`, 97 assets, аудит, список змін, контрольні суми й готовий `community.json`. У Windows-комплекті 1.1.0 канал уже активований і перевірений.

## Новий мод після обговорення в Discord

1. Зафіксуй рішення спільноти в issue: посилання на обговорення, точний мод, версія й причина зміни.
2. Створи окрему копію повного модпаку. Додай мод, залежності й потрібні серверні конфігурації.
3. Для Modrinth можна створити кандидата з добором обов’язкових залежностей:

```powershell
python -m tools.modrinth_add --pack D:\Packs\Revolution --out D:\Packs\Candidate --version MODRINTH_VERSION_ID --java "C:\Java\jdk-21\bin\java.exe"
```

Наявні проєкти визначаються за SHA-512. Required-залежності обробляються рекурсивно. Для нової залежності без version ID обирається стабільний сумісний реліз; конфлікт зафіксованих версій зупиняє підготовку. Початкова папка збережена. Для CurseForge додай дозволені файли вручну; аудит перевірить їх так само.

4. Переглянь аудит і протестуй кандидат на тестовому сервері. Метадані не доводять відсутність runtime-конфліктів Mixin або скриптів.
5. Створи підписаний реліз із наступною ревізією:

```powershell
python -m tools.release_tool build --pack D:\Packs\Candidate --out D:\Releases\pack-r2 --private D:\Private\revolution-release.pem --revision 2 --version 2026.09.15 --repo idenoff-cmyk/revolution-launcher-updates --java "C:\Java\jdk-21\bin\java.exe" --previous D:\Releases\pack-r1\manifest.json --notes D:\Packs\notes.txt
```

Потрібні Python-залежності лаунчера та JDK 21 (source-file mode). Maven-бібліотеки завантажуються з перевіркою SHA-256. Матриця аудиту зафіксована для NeoForge 21.1.250 / FML 4.0.44; перед зміною ядра її потрібно перевірити.

Перевірки: CRC JAR, SHA-256, TOML, вкладені JarJar, required-залежності, діапазони Maven, версія FML та дублікати основних mod ID. Код модів не запускається.

## Публікація

Потрібен [GitHub CLI](https://cli.github.com/) із доступом до репозиторію:

```powershell
gh auth login --hostname github.com --web --git-protocol https
python -m tools.publish_release --release D:\Releases\pack-r2 --repo idenoff-cmyk/revolution-launcher-updates
```

Інструмент перевіряє локальні підписи й хеші, створює draft release, завантажує assets, звіряє SHA-256 від GitHub, публікує незмінний реліз і **останнім кроком** атомарно змінює `channel/stable.json`. Якщо завантаження не завершено або GitHub не підтвердив digest, канал зберігає попередню версію.

Обліковий запис GitHub не вбудовується в лаунчер. Публікуй моди згідно з ліцензіями авторів. Не включай світи, акаунти, приватні логи, API keys або ключ підпису.

Після першої публікації перевір URL каналу, заміни `community.json` поруч із EXE готовим файлом із релізу й перезапусти лаунчер. Наступні зміни каналу розповсюджуються без перевипуску EXE.

## Ключ підпису

Приватний ключ потрібен лише адміністратору. Тримай резервну копію в захищеному сховищі поза GitHub і ZIP лаунчера. У застосунок потрапляє лише публічний ключ.

Для іншого незалежного каналу:

```powershell
python -m tools.release_tool init-key --private D:\Private\new-channel.pem
```

Команда не перезаписує існуючий ключ. Втрата приватного ключа потребує розповсюдження нового публічного ключа клієнтам.

## Конфігурації

Підписаний реліз вважає включені конфігурації обов’язковими: вони синхронізуються так само, як моди. UI-експорт створює лише чернетку з `preserve: true` для конфігурацій; вона не є підписаним каналом.

Нові моди не встановлюються безпосередньо з повідомлень Discord. Авторитетне джерело — реліз, схвалений адміністратором.
